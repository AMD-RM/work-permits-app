# تصاريح العمل — Elsewedy Polymers

تطبيق ويب بسيط لطلب تصاريح العمل ومراجعتها من المشرف، بديل عن التصريح الورقي.

## هيكل المشروع

```
work-permits-app/
├── server.js          # سيرفر Node.js بسيط (يخدم الموقع + يخزن البيانات)
├── package.json
├── data/
│   └── storage.json   # هنا بتتخزن كل الطلبات وبيانات دخول المشرف (بيتعمل تلقائي)
└── public/
    ├── index.html      # الواجهة
    ├── style.css        # التصميم
    ├── app.js           # منطق التطبيق (فورم العامل + لوحة المشرف)
    ├── manifest.json    # إعدادات الـ PWA (اسم التطبيق، الألوان، الأيقونات)
    ├── sw.js            # service worker (يخلي التطبيق يفتح فورًا ويشتغل كأبليكيشن حقيقي)
    └── icons/           # أيقونات التطبيق (مأخوذة من لوجو Elsewedy Polymers)
```

## طريقة التشغيل (من جوه VS Code)

1. افتح التيرمينال في VS Code جوه فولدر المشروع.
2. ثبّت الباكدجات مرة واحدة بس:
   ```bash
   npm install
   ```
3. شغّل السيرفر:
   ```bash
   npm start
   ```
4. هيظهرلك في التيرمينال لينكين:
   - `https://localhost:3000` — تفتحه من نفس الجهاز.
   - `https://<رقم آي بي الجهاز>:3000` — تفتحه من أي موبايل أو جهاز تاني **على نفس شبكة الواي فاي**، وده اللي هيخلي العمال يبعتوا الطلبات من موبايلاتهم والمشرف يشوفها من جهازه.

> السيرفر لازم يفضل شغال (التيرمينال مفتوح) عشان الأبليكيشن يفضل شغال ومتاح للكل.

## أول مرة تفتح اللينك (تحذير الشهادة)

السيرفر بيولّد شهادة HTTPS محلية بنفسه أول مرة يشتغل (مش من جهة معتمدة زي المواقع العادية)، فكل جهاز (موبايل/لابتوب) هيشوف تحذير زي **"الاتصال غير آمن" / "Your connection is not private"** أول ما يفتح اللينك. ده طبيعي ومتوقع لأنها شبكة داخلية:

- **Android/Chrome:** دوس "Advanced" (متقدم) ثم "Proceed to ... (unsafe)".
- **iPhone/Safari:** دوس "Show Details" ثم "visit this website" وأكّد.

بعد أول مرة، المتصفح بيفتكر القرار ومش هيسألك تاني على نفس الجهاز.

## تثبيت الأبليكيشن على الموبايل (PWA)

الموقع ده Progressive Web App — يعني تقدر "تثبته" على شاشة الموبايل الرئيسية زي أي أبليكيشن عادي، من غير متجر تطبيقات:

**Android (Chrome):**
1. افتح لينك `https://<آي بي السيرفر>:3000` من كروم على الموبايل (واقبل تحذير الشهادة أول مرة زي فوق).
2. هيظهر زرار **"⬇ تثبيت التطبيق"** فوق في الهيدر — دوس عليه.
   - أو من قايمة المتصفح (⋮) اختار **"إضافة إلى الشاشة الرئيسية" / "تثبيت التطبيق"**.
3. هتظهر أيقونة Elsewedy Polymers على الشاشة الرئيسية، وبفتحها هيشتغل الأبليكيشن full-screen من غير شريط عنوان المتصفح.

**iPhone (Safari):**
1. افتح نفس اللينك من Safari (لازم Safari تحديدًا، مش كروم).
2. دوس على زرار المشاركة (المربع وفيه سهم لفوق) ↑
3. اختار **"إضافة إلى الشاشة الرئيسية" / Add to Home Screen**.

> الأبليكيشن دلوقتي شغال على HTTPS تلقائيًا (شهادة محلية تتولّد أول تشغيل)، فزرار "تثبيت" هيظهر عادي على الواي فاي الداخلي بعد ما تقبل تحذير الشهادة مرة واحدة زي فوق. لو عايز شهادة حقيقية معترف بيها (من غير تحذير خالص)، الحل الوحيد إنك تستضيف السيرفر على دومين حقيقي بـ HTTPS معتمد (Render/Railway/VPS) بدل الشبكة الداخلية.

## بيانات دخول المشرف (افتراضية)

- **اسم المستخدم:** `supervisor`
- **كلمة المرور:** `1234`

تقدر تغيّرها من جوه لوحة المشرف نفسها بعد الدخول (زرار "⚙ تغيير بيانات الدخول").

## البيانات

كل الطلبات وبيانات الدخول بتتخزن في ملف `data/storage.json` على نفس الجهاز اللي شغّال عليه السيرفر.
- اعمل نسخة احتياطية من الملف ده بشكل دوري (ممكن تنسخه يدويًا أو تحطه في مجلد متزامن زي OneDrive/Google Drive).
- لو عايز تصفّر البيانات، احذف الملف وهيتعمل تاني فاضي أول ما تشغّل السيرفر.

## ملاحظة عن الأمان

نظام الدخول ده حماية بسيطة (يوزر + باسورد) مناسبة للاستخدام الداخلي، لكنه مش نظام أمان على مستوى إنتاجي حقيقي (زي HTTPS + تشفير + صلاحيات متعددة). لو هيتفتح على الإنترنت العام (مش بس شبكة داخلية)، لازم تفكر في:
- تشغيله خلف HTTPS (مثلاً عبر Nginx أو خدمة استضافة زي Render/Railway).
- كلمة مرور أقوى من الافتراضية.
- عمل نسخ احتياطي دوري لملف البيانات.

## لتشغيله دايمًا شغال (اختياري)

لو عايزه يفضل شغال حتى لو قفلت VS Code، ممكن تستخدم أداة زي [pm2](https://pm2.keymetrics.io/):
```bash
npm install -g pm2
pm2 start server.js --name work-permits
```
